# SwimMate 영상 분석 v2 — 다중 선수 카운팅 기준선

> 상태: 오프라인 실험 · 공개 API/UI 비활성
> 기준일: 2026-09-08

## 현재 우선순위 — 카운트와 DPS

현재 v0.4.1은 스트로크·발차기 이벤트 측정과 같은 구간의 DPS 계산에 집중한다.
자세 평가나 자동 영법 분류 확장은 이 카운트의 실제 정확도를 검증한 뒤 진행한다.
RTMPose 가중치를 새로 학습한 버전이 아니라, 포즈 결과를 횟수로 변환하는 시간
신호 처리와 측정 계약을 개선한 버전이다.

- 팔 0.30초·킥 0.09초로 평활화 분리, 실제 시간 간격으로 재표본화
- 검출 누락·긴 관절 가림을 구간 경계로 처리하고 미관측 구간의 가짜 피크 제거
- 큰 피크 주변의 잔떨림 중복과 프레임 반올림에 의한 빠른 킥 병합 개선
- 한쪽 팔만 보이는 결과나 신호 공백이 있는 후보를 전체 횟수로 제시하지 않음
- 영상 SHA-256에 연결된 포즈 캐시로 GPU 재추론 없이 같은 입력 재평가
- 실제 선수 ID·시간 구간·이동 거리를 연결한 DPS: 자유형/배영은 팔 한 번과 양팔
  사이클 기준을 함께 출력하고, 평영/접영은 동시 팔 한 주기를 사용
- 거리가 없거나 횟수가 미확정이면 DPS는 null. 발차기를 못 세더라도 팔 횟수가
  신뢰 조건을 충족하면 DPS 계산 가능
- 영상 확인에 따른 선수별 출발·활주 구간을 팔 집계에서 제외하는 선택 입력 지원.
  자동 구간 분류나 독립 정답은 아니며 입력 출처·원본 해시를 보존한다. 발차기와 전체
  거리는 유지하고, 관절 공백 검사를 완화하지 않는다. 어시스턴트 보정만으로 DPS를 확정하지 않는다.

25m 거리 보충과 팔 후보 13→9 분리 결과·한계는
[v0.4.1 후속 보고서](../analysis_v2/evaluation/results/2026-09-08-v0.4.1-phase-review.md)에 기록했다.

재현 명령과 거리 입력 형식은 [실험 README](../analysis_v2/README.md), 합성 신호
비교 및 실영상의 미해결 항목은 [v0.4 검증 보고서](../analysis_v2/evaluation/results/2026-09-08-v0.4-counting-dps.md)에 있다.
아래 v0.2 설명과 당시 결과는 개발 이력이며, 현재 실행은 사람 검출기를 사용하는
`lane-rtmpose`와 원본 모든 프레임 분석을 권장한다.

## 목표

대회 영상처럼 한 프레임에 여러 선수가 등장해도 선수별 추적 ID를 유지하고,
각 선수의 스트로크·완전한 사이클·발차기 이벤트를 분리해 측정한다.

기존 파이프라인은 MediaPipe `num_poses=1`과 첫 번째 포즈만 사용했으므로
다중 레인 경기를 처리할 수 없었다. v0.2 오프라인 기준선은 다음 순서로 작동한다.

1. 한 번의 장면 안에서 수영장 사각형을 실제 레인 다각형으로 분할
2. 각 레인을 따로 잘라 수평 선수가 세로로 보이도록 90도 회전
3. 사람 검출기를 생략한 RTMPose top-down 추론으로 레인별 포즈 생성
4. 포즈 좌표를 원본 화면으로 복원하고 `L01` 같은 실제 레인 ID 부여
5. 물보라로 잠시 사라진 뒤에도 같은 레인 트랙으로 재연결
6. 레인 ID별 관절 시계열 생성
7. 영법별 팔·발 이벤트 검출
8. 가시성·관측률이 부족하면 수치를 만들지 않고 분석 불가 사유 반환

겹침 타일 MediaPipe 방식은 삭제하지 않고 동일 표본 기준선으로 유지한다.

## ID 유지 원칙

대회 영상에서는 수영 선수가 같은 레인 안에서 이동하고 레인 간 교차는 거의
발생하지 않는다. 이 제약을 이용해 다음 비용이 가장 낮은 연결을 전체적으로 찾는다.

- 이전 속도로 예측한 선수 중심과 새 검출 중심의 거리
- 레인 축 위치 차이
- 주요 관절의 정규화 거리
- 바운딩 박스 겹침

선수가 잠시 물보라에 가려져도 제한 프레임 안에는 이전 트랙과 다시 연결한다.
물리 레인 다각형이 주어지면 검출 순서와 긴 가림에도 같은 `Lxx` ID를 재사용한다.
다만 장면 전환 뒤에는 레인 다각형 자체가 무효가 될 수 있으므로 같은 트랙으로
이어 붙이지 않는다. 얼굴 재인식은 개인정보 위험과 수영모·고글 환경의 낮은
신뢰도 때문에 사용하지 않는다.

## 카운팅 원칙

- 자유형·배영: 왼팔·오른팔 이벤트를 병합해 한 팔당 1회로 집계. 호환용 완전한
  사이클 수는 횟수/2의 정수 부분이며, DPS와 킥 비율은 소수 사이클을 보존
- 평영·접영: 좌우 동시 이벤트를 시간 허용 범위 안에서 하나로 병합
- 자유형·배영 킥: 양 발목 상대 신호의 양·음 극값을 각각 유효 비트 후보로 사용
- 평영: 양 발목 간격의 주기적 최대값 사용
- 접영: 양 발목 평균 움직임의 주기적 최대값 사용
- 발목 가시성이 기준보다 낮으면 킥 수를 숨기고 `legs_not_visible` 반환
- 전체 처리 프레임 중 한 선수의 연속 관측률이 60% 미만이면 짧게 조각난 트랙으로
  보고 팔·발 카운트를 모두 숨김

현재 결과는 포즈 좌표와 적응형 피크 검출을 사용한 기준선이다. 수동 검수 이벤트가
쌓이면 동일한 입출력 계약을 유지하면서 TCN/1D CNN 이벤트 탐지 모델로 교체한다.

## 2026-08-26 실제 영상 비교

시드 `20260826`으로 자유형·배영·평영·접영 각 5개, 총 20개 다중 선수 대회 영상을
선정했다. 처음 지정한 구간 중 9개에는 방송 장면 전환이 있었으므로 HSV 히스토그램
기반 전환 점수로 확인한 뒤 하나의 고정 장면만 남겼다. 같은 715개 프레임을 6 FPS로
MediaPipe 겹침 타일 기준선과 레인 RTMPose top-down 후보에 입력했다.

| 지표 | 기준선 | RTMPose 후보 |
| --- | ---: | ---: |
| 프레임당 평균 검출 레인 | 1.868 | 4.897 |
| 60% 이상 안정 트랙 | 7 | 93 |
| 팔 카운트 출력 트랙 | 4 | 73 |
| 킥 카운트 출력 트랙 | 4 | 73 |

프레임당 검출 범위는 162.2% 증가했다. 하지만 독립 이벤트 정답이 0개이고 원거리
영상의 발차기는 수동 검수 시트에서도 판독하기 어려웠다. 따라서 위 값은 정확도가
아니며, 카운트 정확도 상태는 계속 `미검증`이다. 자유형 7초 구간에서 팔 2회처럼
육안상 과소 계수 가능성이 큰 출력도 확인되어 공개 게이트를 통과하지 못했다. 전체
예측과 보류 사유는 `analysis_v2/evaluation/results/2026-08-26-report.md`에 기록했다.

2026-08-28 Galaxy Book4 Pro 실측에서는 기존 ONNX Runtime이 CPU만 사용하고
있음을 확인했다. OpenVINO에서 RTMPose-M은 Arc GPU 36.24fps(단일 레인),
RTMPose-X는 10.06fps였다. 자동 프로필은 M/GPU, 명시적 `quality` 프로필은
X/GPU를 사용한다. 다만 대형 모델도 킥 가시성을 통과하지 못했고 독립 이벤트
정답이 없으므로 정확도 개선으로 기록하지 않는다. 상세 결과는
`analysis_v2/evaluation/results/2026-08-28-galaxy-book4-pro.md`에 있다.
20개 고정 구간의 M/GPU 처리량은 기존 1.327fps에서 7.724fps로 약 5.8배
증가했지만, 정답 없는 검출 범위 변화는 정확도 변화로 간주하지 않는다.

기존 학습 데이터 감사에서는 폴더 라벨 오염, 동일 영상 중복·상충 라벨, 학습
데이터 재평가 누수, 사람 검증 라벨 0건을 확인했다. 이 상태의 재학습은 차단하며
`analysis_v2.annotation`으로 만든 팔·킥 이벤트 타임라인을 서로 다른 검수자가
확인한 뒤에만 정답으로 사용한다.
빈 검정·수영장색 단색·무작위 노이즈 입력에서는 top-down 제공자가 모두 포즈 0개를
반환했지만 실제 물보라·레인 로프에 대한 오탐률은 별도 정답 프레임으로 검증해야 한다.

## 공개 전 필수 통과 조건

1. 권리 확인된 영상만 학습·평가에 포함
2. 같은 원본·채널·선수·경기·재업로드를 데이터 분할 사이에 섞지 않음
3. 스트로크 10회당 평균 절대 오차 1회 이하
4. 평가 영상 90% 이상에서 정답 대비 ±1 스트로크
5. 발차기는 커버리지와 오차를 함께 공개하고 가림 영상에서 결과를 보류
6. 장면 전환·리플레이·배속 구간 자동 차단
7. 실제 대회 영상의 레인별 ID 유지율과 ID 전환 횟수 측정
8. 별도 비동기 Worker, 영상 보관·삭제 정책, 소유권 검증, E2E 완료

이 조건 전에는 README·릴리즈 노트·Notion 서비스 설명서에서 공개 기능으로
표현하지 않는다.
