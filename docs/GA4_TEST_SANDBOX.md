# GA4 검증 환경 (운영 수집과 분리)

운영 수집은 계속 OFF. 운영 계정의 자격/동의 검사를 우회하지 않는다.
전용 화면은 로그인·DB 쓰기 없이 가상 이벤트만 생성한다.
운영 호스트에서 열면 Google 코드를 로드하지 않으며 localhost에서만 연결 가능하다.

## 지금 실행

`python -X utf8 scripts/analytics_test_server.py`

브라우저: `http://localhost:8766/analytics_test`

기본은 로컬 로그 모드이며 Google 요청 없음. 서버는 127.0.0.1:8766에만 바인딩하고
검증 HTML/JS 두 파일과 테스트 설정만 제공한다. 저장소·인증 파일은 제공하지 않는다.

## 실제 Tag Assistant 연결에 필요한 것

1. 별도 GA4 테스트 속성/웹 스트림의 측정 ID와 별도 GTM 웹 컨테이너를 만든다.
2. 기존 확장 JSON을 테스트 컨테이너로 가져올 때 모든 GA4 대상 ID를 테스트 ID로
   변경한다. 설정·태그 전체를 재내보내 검토하기 전에는 로드를 활성화하지 않는다.
   테스트 ID만 서버에 넣는 것으로 컨테이너 내부 대상까지 자동 변경되지는 않는다.
3. 아래 환경변수를 **로컬 서버 프로세스에만** 설정하고 재시작한다.

```
ANALYTICS_TEST_ENABLED=true
ANALYTICS_TEST_GTM_CONTAINER_ID=별도 테스트 컨테이너 ID
ANALYTICS_TEST_GA4_MEASUREMENT_ID=별도 테스트 측정 ID
```

운영 ID·누락·잘못된 ID는 서버와 브라우저에서 차단한다. 운영 활성화 플래그와 무관하다.
GTM 미리보기 대상은 위 localhost 주소. 열린 검증실에서 태그 로드에 명시적으로 동의한다.
Tag Assistant 연결, 거부 시 무요청, 이벤트별 1회 발화, GA4 실제 payload, 안전한 URL,
테스트 속성 수신을 확인한다. debug_mode는 운영 통계 격리 수단이 아니며 별도 속성을 쓴다.
연결 중단 버튼은 동의 거부·쿠키 정리·리로드 후 수동 재동의 상태로 돌아간다.

이 화면은 전송 배선의 합성 검증이다. 실제 사용자 로그인 자격/업무 API 성공 시점은
별도의 앱 테스트로 검증하며 합성 버튼 통과만으로 운영 계측 검증 완료라 하지 않는다.

현재 별도 테스트 ID가 없어 실수신은 미검증. 운영 컨테이너를 게시할 필요가 없다.
