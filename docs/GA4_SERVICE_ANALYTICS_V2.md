# 관리자 이용 현황을 GA4로 확장하는 측정 설계 v2

2026-10-25. 운영 수집은 OFF. GTM 파일 검토/가져오기만으로 연동 완료가 아니다.
목적은 관리자 수치의 단순 복제가 아니라 그 수치를 만드는 일반 사용자 행동을
화면/기기/경로별로 탐색하는 것이다. 기존 DB·관리자 분석은 그대로 유지한다.

## 범위와 분석 기준

- 일반 로그인 사용자의 명시적 분석 동의가 있어야 태그를 로드한다.
- 랜딩·홈·데이터·일지·플랜·리포트·풀사이드·수영장·커뮤니티·챌린지·코치·클럽·
  AI 코치·프로필·정보/가이드 화면을 허용 목록으로 계측한다.
- 관리자·QA·데모·공유 토큰 경로·미리보기·미분류 계정은 제외한다.
- **익명 유입/회원가입/로그인 횟수는 이번 버전에서 수집하지 않는다.**
  해당 메뉴를 방문해도 로그인 자격 확인이 없으면 수집하지 않는다.
- 기기/브라우저 등 GA4 기본 정보는 활성화 후 Google 측정 환경에서 검증한다.
  유입 정보는 URL 쿼리와 referrer를 제거하므로 유입 경로 분석에 제한이 있다.
  UTM·검색어·전체 URL을 뒤늦게 자동 수집하도록 켜서는 안 된다.
- 관리자 합계는 DB 기준, GA4는 동의한 관측 사용자 기준이다. GA4 관측 사용자 수를
  전체 회원/전체 활성 회원 수로 표시하지 않는다. 과거 로그를 GA4 실적으로 생성하지 않는다.

## 이벤트와 원장 매핑

| 이벤트 | 계측 시점 | 주의 사항 |
|---|---|---|
| page_view | 허용 화면에서 동의 후 1회 | 리로드는 새 조회, 실회원 수 아님 |
| menu_navigate | 같은 도메인의 다른 허용 메뉴 링크 클릭 | 실제 도착은 다음 page_view로 확인 |
| training_log_view/start/create/error | 기존 신규 수기 일지 흐름 | 수정·수입·스크린샷 저장 제외 |
| report_view | 리포트 진입 | 저장 직후 진입 여부는 경로로 별도 분석 |
| community_post_create | 신규 게시글 API 성공 | 수정 제외, 제목/내용/분류/ID 전송 안 함 |
| community_comment_create | 댓글/답글 API 성공 | 내용·대상 글/작성자 전송 안 함 |
| plan_create | 서버 플랜 저장 성공 | 로그인 전 로컬 저장·서버 실패 제외 |
| plan_share_link_ready | 공유 URL 조회 성공 | 공유 완료/실제 열람/새 토큰 발급과 다름 |
| coach_join | 새 코치 관계 생성 성공 | already_exists 응답 제외 |
| coach_task_create | 내부 코칭 과제 생성 성공 | 과제 내용/학생 정보 제외 |
| coach_task_complete | 내부 코칭 과제 완료 성공 | already_done 응답 제외 |
| challenge_join | joined 응답 | already_joined 제외 |

공통 매개변수: screen_name(고정 메뉴 코드), event_schema_version=2.
menu_navigate만 destination_screen(고정 목적 메뉴 코드)을 추가한다.
기존 수기 일지의 input_method/manual·분류된 error_code 외 자유 입력값은 금지한다.
click 리스너는 허용 메뉴 링크만 보고 fetch나 응답 본문을 가로채지 않는다.
서버에서 직접 실행된 동작·광고 차단·동의 전 이벤트·이탈 중 전송 손실은 GA4에서
누락될 수 있으므로 DB 원장과 일치한다고 약속하지 않는다.

## 개인정보·활성화 게이트

범위가 확대되어 기존 v1 동의를 재사용하지 않는다. 동의 저장 키는 v2로 변경한다.
서버는 아래 설정이 모두 준비되어야 enabled=true를 반환한다.

```
PRODUCT_ANALYTICS_ENABLED=true
ANALYTICS_PRIVACY_REVIEWED=true
ANALYTICS_POLICY_VERSION=2026-10-v2
```

GTM/GA4 ID는 기존 값을 유지한다. 현재 위 활성화 플래그는 변경하지 않았다.
개인정보 안내의 실제 범위 수정, 거부·철회, QA 제외 및 Google 실제 payload 확인 후
소유자 확인을 받아 활성화한다. 선택 설정 UI는 수집이 비활성일 때 표시되지 않는다.

## GTM 가져오기와 분석 구성

가져오기 파일: `output/ga4/GTM-5TQRKVQ5-service-wide-20261025.json`.
사용자가 다시 내보낸 검토 완료 JSON을 기반으로 기존 7개 태그를 보존하고
새 이벤트 태그 9개, 트리거 9개, DLV - destination_screen 변수 1개를 추가했다.
기존 자동 이벤트 감지와 사용자 제공 데이터 수집 OFF 설정을 유지한다.
최종 태그 16개, 변수 8개. 미사용 원본 트리거 1개를 포함해 트리거는 17개이다.
가져오기 미리보기에서 기존 작업공간/병합/충돌 덮어쓰기와 변경 내역을 확인한다.
새 태그는 safe_page_location/referrer/title 공통 매개변수를 그대로 사용한다.

GA4 맞춤 측정기준에는 screen_name, destination_screen, input_method,
error_code, event_schema_version을 이벤트 범위로 등록한다. 데이터가 자동으로
과거에 소급 적용된다고 해석하지 않는다.

권장 보고서:
1. 메뉴 사용: screen_name별 관측 사용자·조회·참여 시간, 기간별 비교.
2. 경로 탐색: 홈 → 플랜 → 일지 → 리포트, 실제 이동과 링크 클릭 구분.
3. 일지 퍼널: 진입 → 작성 시작 → 저장 성공, 오류 분기.
4. 커뮤니티: 진입 → 게시글/댓글 참여. QA 데모 활동은 제외.
5. 코칭: 연결 → 과제 생성 → 완료. 코치와 수강생이 다른 사용자이므로
   한 사용자 전환 퍼널로 이어붙이지 않는다. DB의 관계 집계가 별도로 필요하다.

검증 시나리오: 동의/거부/철회, QA/관리자 제외, 파라미터 allowlist,
모든 메뉴에 잘못된 report_view가 찍히지 않는지, 저장 실패/수정/중복 응답 제외,
자동 측정 OFF, Google 네트워크 요청의 개인정보/URL 쿼리/중복 여부.
지금은 구현과 정적·로컬 테스트 단계이며 실제 GA4 수신/통계 성과는 미검증이다.
