# 관리자 영법 분석 TEST

접속 위치: [SwimMate 관리자](https://swimtech.vercel.app/admin#video-lab) → **영법 분석 TEST**.
일반 회원용 영상 분석을 다시 활성화한 것이 아니라, 기존 로컬 검수실을 운영 관리자 화면에 연결한 실험 기능이다. 실제 계정 권한은 API에서 확인한다.

## 현재 검증 상태 (2026-09-09)

운영 UI와 API 배포, 익명 API 401 거부, GitHub 핵심 테스트 통과를 확인했다.
로컬 중계 통합 환경에서는 실제 `이강해.mp4`의 5.7~17.7초 구간을 업로드해 H.264 재생·RTMPose-X/OpenVINO GPU 추론·비교·내보내기·자기 프로젝트 삭제까지 통과했다. 320~1920px 6개 폭에서 가로 넘침과 브라우저 오류가 없었다.
팔 후보 14개·킥 후보 12개는 관측 공백으로 확정 횟수가 보류되며 모델 DPS도 보류다.

**운영 Vercel→Render→PC 전체 영상 E2E는 아직 통과하지 않았다.** 최초 `.env` 로그인 실패를 해결하기 위해 관리자 브라우저의 명시적 PC 연결 승인 방식을 추가했다. 승인 후 운영 검증이 필요하다. `tmp/analysis_v2/admin-local-browser/report.json`은 로컬 증적이고 `tmp/analysis_v2/admin-browser/report.json`과 혼동하지 않는다. Notion 릴리즈 노트·서비스 설명서에는 운영 검증 전 완료 기능으로 반영하지 않는다.

후속 업로드 멈춤 수정: 처리기 없이 H.264 원본 재생·새로고침, HEVC 미지원 안내, 320~1920px 레이아웃, 명시적 PC 승인, CSS/JS/영상 HTTP 오류 0건을 로컬 브라우저에서 확인했다. `임가은_3.mp4` 원본은 HEVC이며 테스트 Chromium에서는 PC 호환 변환이 필요했다. `.env` 비밀번호 변경 없이 아래 연결 승인 방식으로 진행할 수 있다.

2026-09-10 지속 연결 변경: 55분/15분 유휴 자동 종료를 기억한 PC에서 제거했다. 45분마다 인증을 갱신하고 네트워크·서버 재시작 후 자동 재연결한다. 로컬 브라우저에서 PC 등록·갱신·연결 해제·해제 후 401, 320~1920px 레이아웃과 리소스 오류 0건을 확인했다. Windows DPAPI 저장/복원·중복 실행 방지와 가상 시계의 2시간 이상 유지도 테스트한다. 실제 운영의 기존 일회용 처리기에서는 영상 변환 3건·분석 반환 1건 완료 로그를 확인했으나 전체 운영 UI 자동 E2E와 모델 정확도 통과를 의미하지 않는다.

## 이용 흐름

1. 관리자 계정으로 로그인한 뒤 `영법 분석 TEST` 메뉴를 선택한다.
2. 사용 권한이 있는 64MB·60초 이하 원본 영상을 선택한다. 관리자당 3개, 서버 전체 6개까지만 보관한다.
3. 지원되는 원본은 업로드 직후 재생할 수 있다. HEVC 등 미지원 원본에는 변환 안내를 표시한다. 처리기가 H.264 무음 영상을 준비하면 정확한 프레임 이동과 분석 조건 지정이 활성화된다. 재생 오류가 남아 있으면 `재생 상태 다시 확인`을 누른다.
4. 50m 경기의 실제 레인 번호·영법·시작/종료를 정하고, 시작 장면의 선수 몸통을 클릭한다. 화면의 위아래 순서로 레인을 추측하지 않는다. 장면 전환 뒤에는 같은 선수를 클릭해 시간별 확인점을 추가할 수 있다. 모든 확인점이 같은 선수임을 체크해야 분석을 시작할 수 있다. 고정 ROI 드래그는 관리자 화면에서 제거했다. 분석 중에는 저속 재생·프레임 이동·A/K로 팔/킥 시점을 직접 기록할 수 있다. 가려져 셀 수 없으면 `판독 불가`를 사용한다.
5. 수기 기록 저장 후 모델 결과를 연다. 후보 시점, 관절 추정, 관측 공백, 수기 기록과의 시점 일치도를 비교한다.
6. 필요한 기록을 JSON으로 내보내고 영상을 삭제한다. 독립 기록과 모델을 본 뒤의 보정 기록은 구분한다.

풀 길이를 부분 구간의 이동 거리로 자동 간주하지 않는다. 거리 입력이 없거나 모델의 전체 스트로크 횟수가 보류되면 모델 DPS도 표시하지 않는다. 1인 시점 일치도는 검증된 정확도가 아니다.

## 이동 카메라의 선택 선수 추적 (2026-09-10)

- 새 관리자 분석 요청은 `target={lane_id, race_distance_m:50, confirmed:true, checkpoints:[{time_sec,x,y}]}`가 필수다. 시작 프레임의 확인점, 좌표 범위, 시간 순서, 레인 번호를 서버에서도 검증한다. 기존 고정 ROI 결과는 읽을 수 있고 별도 로컬 검수실은 기존 동작을 유지한다.
- PC는 배경 특징점의 양방향 optical flow와 RANSAC affine 변환으로 팬·줌을 추정하고, 선수 위치·크기에 따라 탐색 창을 움직인다. 창 안의 여러 사람은 모두 후보이며 몸통 위치·크기·약한 색상 증거로 한 명만 연결한다. 탐색 창 자체를 선수 ID로 취급하지 않는다. [OpenCV optical flow](https://docs.opencv.org/4.x/dc/d6b/group__video__track.html), [affine 추정](https://docs.opencv.org/4.x/d9/d0c/group__calib3d.html)을 사용한다.
- 모호한 겹침, 검증하지 못한 카메라 이동, 0.2초를 넘는 미검출은 자동 재식별을 막고 사용자 확인점까지 집계 관측을 중단한다. 짧은 공백도 전체 구간 집계는 확정하지 않는다. 관측된 후보와 미확인 구간은 따로 표시하며, 이를 전체 경기 횟수/0회/정확도로 바꾸지 않는다.
- 결과에서 선택 선수 관절 표시와 `다시 볼 구간`을 확인할 수 있다. 수기 기록 저장 전에는 `선수 확인점 수정 · 재분석`으로 다시 시도한다. 이미 본 모델 답안 이력은 유지되어 재분석을 독립 블라인드 라벨로 둔갑시키지 않는다. 수기 기록을 저장한 조건은 변경하지 않는다.
- 50m는 경기 맥락이지 자동 측정 거리나 전체 경기 집계를 뜻하지 않는다. 기존 60초·64MB 업로드 한도는 유지한다. 킥 가림/수중 미관측을 영상만으로 복원하지 않는다. 레인 번호 자동 인식이나 검증된 선수 재식별 모델은 아니다.
- 합성 다중 선수·팬·줌·겹침·카메라 단절·재확인 테스트와 로컬 UI/PC 모델 반환을 검증했다. 실제 저해상도 50m 방송 샘플 90프레임에서는 20프레임만 연결되어 전체 집계가 보류됐다. **이동 카메라 실영상의 완전 자동 집계 정확도는 아직 검증되지 않았으며 실제 샘플 검수/모델 개선이 필요하다.**
- 서비스 워커는 공개 정적 화면/스타일만 캐시한다. 관리자 API·미디어·Range 요청은 가로채지 않고 206/실패/비공개 응답은 저장하지 않는다. 활성화 시 기존 SwimMate 캐시를 지우며, 별도 앱의 캐시는 건드리지 않는다. 이는 관찰된 `Cache.put: 206 unsupported` 오류 수정이지 해당 오류만이 모든 재생 장애의 원인이었다는 주장은 아니다.

## 실행 구조와 제한

`/admin`의 검수 화면 → 인증된 임시 API 저장소/작업 대기열 → 관리자 PC 처리기 → 기존 `analysis_v2` 모델 → 관리자 검수 화면.

- UI는 Vercel, 경량 중계 API는 Render에서 동작한다. 기존 RTMPose·OpenVINO 품질 프로필은 PC에서 실행하며 새 외부 생성형 AI API를 호출하지 않는다.
- 관리자 PC 처리기가 꺼져 있으면 작업 영역에 연결 필요 안내·연결 명령을 표시한다. 지원되는 원본은 재생할 수 있지만 새 분석 시작 버튼은 비활성화한다. 업로드된 변환 작업은 연결 후 처리하며 자동으로 성공 처리하지 않는다. 새 유료 서버나 터널을 만들지 않았다.
- 처리기는 외부로 나가는 HTTPS 요청만 사용한다. 1시간짜리 작업 전용 접근 토큰은 메모리에만 보관하며 기억한 PC는 45분마다 갱신한다. 이 토큰으로 일반 관리자 데이터에는 접근할 수 없다.
- 지속 연결 정보만 Neon의 `video_worker_devices`에 저장한다. 계정당 최대 5대, PC 이름·계정 ID·비밀값 해시·세션 버전·사용/만료/해제 시각만 기록하고 원본 비밀값이나 영상은 저장하지 않는다. 90일간 미사용하면 갱신할 수 없다. 이 등록 정보는 웹 서버 재배포에도 유지된다.
- 5초 작업 폴링에서는 DB를 조회하지 않는다. 등록·45분 인증 갱신·명시적 관리에서만 DB를 사용한다. 갱신 요청의 서버 서명이 틀리면 DB에 접근하기 전에 거부한다. 처리기 상시 연결은 PC와 웹 서버의 실행 시간 및 통신 자원을 사용한다.
- 관리자 연결 해제는 현재 단일 API 프로세스에서 즉시 작업 토큰·진행 작업을 무효화한다. 서버 재시작 시 이전 접근 토큰은 프로세스 식별자 불일치로 거부되고, DB의 해제/만료 상태를 재검사한 뒤 새 토큰을 발급한다. 비밀번호·관리자 권한 변경은 다음 갱신 시 반영되므로 이미 발급한 접근 토큰의 최대 잔여 수명은 1시간이다. 다중 API 프로세스는 지원하지 않는다.
- 업로드 청크는 1MB, 원본 전체 예약 한도는 192MB, 재생 파일은 각 32MB, 결과 JSON은 각 3MB로 제한한다. 작업 임대 만료·취소 이후에는 결과를 제출할 수 없다.
- 영상·라벨·결과는 Neon이나 일반 훈련 일지에 저장하지 않는다. 원본의 SHA-256을 업로드 완료와 처리기 다운로드 후 확인한다.
- 업로드 1시간 후 조회가 만료되고, 다음 API 접근/처리기 폴링에서 만료 파일을 정리한다. 서버 재시작·비활동 종료 시 더 일찍 사라질 수 있다. 처리기 임시 파일은 해당 작업 종료 시 삭제한다. PC 강제 종료 시 운영체제 임시 폴더가 남을 수 있으므로 자동 백업 저장소로 사용하지 않는다.
- 무료 Render의 임시 파일 시스템과 중단 동작은 [공식 Free 서비스 문서](https://render.com/docs/free)를 따른다. 여러 API 인스턴스·영구 저장·24시간 추론을 지원하는 구조가 아니다.
- [Render root directory 범위](https://render.com/docs/monorepo-support) 때문에 배포 API가 저장소 바깥의 모델 모듈을 import하지 않는다. 모델 의존성을 무료 웹 API에 설치하지 않는다.

## 처리기 실행

기존 로컬 영상 모델 실행 환경이 준비된 PC에서 사용한다. 처음에만 다음 명령 후 표시되는 링크를 현재 관리자 계정으로 열고 **같은 연결 코드인지 확인 → 이 PC 기억 선택 → 이 PC 연결 승인**을 누른다. 이후 같은 명령으로 실행하면 저장된 승인을 재사용한다. 브라우저 비밀번호·쿠키를 읽거나 PC로 복사하지 않는다.

```powershell
python -m analysis_v2.workbench.remote_worker
```

연결 코드는 5분 유효하고 관리자 승인을 자동으로 수행하지 않는다. 작업 토큰은 요청을 시작한 PC의 별도 비밀값으로 한 번만 수령할 수 있으며 화면/로그에 노출하지 않는다. 직접 요청하지 않은 코드는 승인하지 않는다. PC 승인 후 원래 `/admin` 탭에서 연결 상태를 확인한다.

Windows 연결 정보는 `%LOCALAPPDATA%/SwimMate/video-worker/`에 현재 Windows 사용자용 DPAPI 암호문으로 저장한다. 임시 저장 파일에도 평문을 쓰지 않는다. [Microsoft DPAPI 문서](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)의 현재 사용자 범위를 사용하며 컴퓨터 전체 계정 공유 옵션은 사용하지 않는다. 계정/기기 교체 시에는 다시 승인한다. Linux/macOS는 `--memory-only`로 실행 중에만 유지할 수 있으며 평문 저장으로 대체하지 않는다.

`/admin` → 영법 분석 TEST → **등록된 PC 관리 · 연결 해제**에서 해당 PC의 권한을 해제한다. `Ctrl+C`는 처리기만 중지하고 승인은 보존한다. 로컬 승인만 지우려면 처리기를 중지한 뒤 `--forget-device`를 사용한다. 강제로 새 승인을 받으려면 `--browser-login`을 지정한다.

기존 자동화의 임시 로그인은 `--env-login`으로 로컬 `.env`의 `ADMIN_ID` / `ADMIN_PW`를 사용할 수 있다. 값은 화면·로그·명령줄에 출력하지 않는다.

```powershell
python -m analysis_v2.workbench.remote_worker --env-login
```

기억한 PC는 기본적으로 유휴/전체 실행 시간 제한이 없다. 필요할 때만 `--idle-timeout 초`·`--max-minutes 분`으로 제한한다. PC 종료·절전·처리기 종료 중에는 분석하지 못한다. PC 재부팅 후 처리기를 다시 실행하면 재승인은 필요 없지만, Windows 로그인 자동 실행 등록은 이번 변경에 포함하지 않았다. 기억하지 않는 승인과 `--env-login`은 기존 55분 임시 모드다. 운영 SwimMate HTTPS 주소와 로컬 QA 주소만 허용한다.

- `scripts/qa_ui_crawler.py`: 정기 운영 QA에서 9개 관리자 메뉴의 모바일 비겹침과 새 검수실의 인증·화면 연결을 확인한다. 이 검사만으로 GPU 추론 통과를 주장하지 않는다.
- `scripts/qa_admin_video_lab.py`: 별도 opt-in 실제 영상 검사. 관리자 로그인, 실제 업로드/재생/추론/비교/내보내기, 1920·1440·1024·768·390·320px 레이아웃, 자기 테스트 프로젝트 삭제를 검사한다. PC 처리기를 먼저 실행해야 한다.

```powershell
python scripts/qa_admin_video_lab.py --video "video/이강해.mp4" --start-sec 5.7 --end-sec 17.7 --distance-m 25
```

처리기 미연결 회귀는 H.264 영상에 `--offline-check`, HEVC 영상에는 추가로 `--expect-unsupported-native`를 지정한다. `--device-check`를 함께 주면 기억한 QA PC를 등록·갱신·UI 해제하고 해제 후 갱신 거부까지 확인한다. 원본 재생/변환 안내·새로고침·분석 버튼 잠금·PC 승인·정적 리소스 오류·자기 테스트 프로젝트 삭제를 검사한다. 로그인이 되는 대상에서만 실행하며 운영 계정을 우회하지 않는다. Windows DPAPI 검사 1개는 Linux CI에서 건너뛰며 실제 Windows에서 별도로 통과해야 한다.

수기 검증 정답을 꾸며내지 않도록 위 스크립트의 팔/킥 기록은 모두 `판독 불가`, 검증 여부는 `false`로 저장한다. 스크립트 통과는 서비스 연결의 증거이며 모델 정확도 향상의 증거가 아니다. 실행별 증적은 Git에서 제외된 `tmp/analysis_v2/admin-browser/`에 보관한다.
