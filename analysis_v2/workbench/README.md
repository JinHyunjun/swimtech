# SwimMate Lab — 로컬 영상 교차 검수실

수영 영상을 올리고, 직접 센 팔·킥 시점과 모델이 찾은 후보를 비교하는 별도 사이트다.
정식 SwimMate와 연결되지 않는 **실험용 로컬 웹 앱**이며 모델의 실제 정확도는 아직 미검증이다.

## 실행

저장소 `C:\swim`에서 기존 오프라인 분석 Python 환경을 사용한다.

```powershell
python -m pip install -r analysis_v2/requirements-workbench.txt
python -m analysis_v2.workbench
```

브라우저에서 **http://127.0.0.1:8765** 를 연다. 서버 종료는 실행한 터미널에서 `Ctrl+C`.
포트가 사용 중이면 `--port 8766`으로 실행한다. PC를 재시작하면 서버를 다시 실행해야 한다.
인터넷에 공개된 주소가 아니므로 다른 PC/휴대폰에서는 접속되지 않는다.
공개 터널·0.0.0.0 바인딩·운영 사이트 연결을 하지 않는다.

`--data-dir <경로>`로 저장 위치를 바꿀 수 있다. 기본은
`tmp/analysis_v2/workbench/`이며 원본·프리뷰·모델 결과·관절 캐시·라벨을 보관한다.
사이트의 **영상 삭제**는 해당 업로드의 자료만 지우며, 처음 선택한 원본 파일은 삭제하지 않는다.

## 검수 순서

1. **영상 선택**: 촬영/이용 권한이 있는 파일을 올린다. 최대 200MB·10분·4K·120fps,
   보관 프로젝트는 12개다. PC에서 재생용 영상을 준비하는 동안 잠시 기다린다.
2. **대상/구간 선택**: 영법과 최대 60초 구간을 입력한다. 화면에서 선수/레인 영역을
   드래그하되 움직이는 선수가 전체 구간 동안 영역 안에 있어야 한다. 한 프로젝트는 한 대상이다.
   여러 선수가 나온다면 같은 영상을 다시 올려 서로 다른 선수 영역으로 각각 검수한다.
   한 영역에서 여러 선수가 교차하면 신원 유지가 보장되지 않는다. 전체 다중 레인 일괄 실행은 CLI 기능이다.
3. **분석 시작**: RTMPose-X `quality` 프로필과 레인별 사람 검출기로 원본 모든 프레임을 분석한다.
   PC 자원 경쟁을 줄이기 위해 한 작업씩 실행하며 대기/실행 중에는 중지할 수 있다.
4. **먼저 직접 기록**: 0.25×/0.5× 재생, 좌우 화살표 또는 프레임 버튼으로 확인한다.
   팔은 `A`, 킥은 `K` 또는 화면 버튼으로 현재 시점을 기록한다. 작은 화면에서는 영상 바로 아래 빠른 기록 버튼을 쓴다. 마지막 기록 취소와 개별 삭제를 지원한다.
   가려져 셀 수 없는 항목은 **판독 불가**를 선택한다. 빈 목록 0회와 구분된다.
5. **수기 기록 저장**: 실제로 이전에도 이 영상의 모델 결과를 보지 않았을 때만 독립 기록 체크박스를 선택한다.
   이미 후보를 확인한 사람은 체크하지 않는다. 체크하지 않은 기록은 보정용으로 분류한다.
6. **모델 결과 열기**: 모델 후보 시점을 눌러 장면으로 이동하고, 관절 추정과 다시 볼 구간을 확인한다.
   결과 공개 전 마지막으로 저장한 독립 기록은 보존하며 공개 후 수정은 보정용으로 따로 저장한다.
7. **내보내기**: JSON에는 분석 조건·원본 해시·수기 시점·공개 여부가 담긴다.
   모델 결과를 연 뒤에는 후보/비교 결과도 포함된다. 파일은 개인 자료로 보관한다.

분석 조건 변경은 수기 기록과 연결을 깨뜨리므로 저장/공개 후 재분석은 막는다.
다른 조건은 새 업로드로 비교한다. 브라우저의 라벨 저장은 자동 저장이 아니므로
이동 전에 **수기 기록 저장**을 누른다.

## 무엇을 1회로 세나

- 자유형·배영: 한 팔의 한 동작 = 1회. 양팔이 한 번씩 움직이면 2회다.
- 평영·접영: 양팔이 동시에 한 주기를 마치면 1회다.
- 교대 킥: 한 발의 한 박자 = 1회. 동시 킥은 두 발이 함께 움직인 한 주기다.
- 횟수뿐 아니라 **어느 순간을 찍는지**도 맞춰야 시점 F1을 해석할 수 있다.
  팔 모델 후보는 몸통 축에서 손목이 머리 방향으로 가장 멀어지는 피크를 사용한다.
  교대 킥 후보는 몸통 횡축의 두 발목 간격 극대/극소, 평영은 발목 간격 극대,
  접영은 평균 발목 위치의 횡축 피크다. 다른 동작 기준으로 라벨링했다면
  시점 차이를 곧바로 오검출로 해석하지 말고 기준부터 맞춘다.

`관측 후보 14개`와 `전체 팔 14회 확정`은 다르다. 관절 공백이 있으면 전체 횟수는
**보류**한다. 관절 공백 표시 또한 실제 물리적 가림 판정이 아닌 재검토 안내다.
가중치를 자동 재학습하거나 사람의 보정 결과를 독립 정답으로 승격하지 않는다.

## DPS와 두 사람 교차 검수

구간의 **실제 이동 거리**를 알 때만 입력한다. 25m 풀이라도 일부 구간이 25m인 것은 아니다.
모델의 팔 횟수가 보류되면 모델 DPS도 보류된다. 수기 거리/팔 횟수로 나눈 값은
사용자 입력에 따른 참고값이지 검증된 모델 DPS가 아니다. 다이빙·잠영 거리를 포함한
편도 DPS와 실제 스트로크 구간만의 DPS 역시 구분해야 한다.

두 사람이 모델 결과를 보지 않고 같은 원본·영법·선수 영역(ROI)·시작/종료 구간을
독립적으로 기록한 뒤 내보내기 파일을 만든다. **사용 방법 → 두 사람의 독립 기록 비교**에서
두 파일을 넣는다. ±0.25초 일대일 대응과 불일치 시점을 출력하며, 판독 불가를 정답 0회로 보지 않는다.
검수자가 서로 달라도 동일한 판단 실수를 할 수 있으므로 합의만으로 모든 영상의 정확도를 보장하지 않는다.

## 프라이버시·재생·성능 제한

- 업로드는 자신의 PC로만 전송한다. Neon·Gemini·운영 API·외부 분석 서비스는 호출하지 않는다.
  초기 패키지/모델 설치 시 파일 다운로드는 필요할 수 있다. 별도 클라우드 AI 호출료는 없고 PC 자원을 사용한다.
- HEVC의 브라우저 오디오 전용 재생 문제를 막기 위해 원본을 유지한 채 무음 H.264 사본을 만든다.
  프리뷰는 긴 변 최대 1280px이며 원본의 프레임 순서와 `frame_index / FPS` 시간축을 사용한다.
  원본이 가변 FPS여도 분석과 동일한 프레임 시간축으로 정규화한다. 실시간 촬영 시간의 정밀 측정과는 다르다.
  프리뷰 프레임 수/길이를 검증하고 불일치 시 업로드를 거절한다.
- 네이티브 비디오 탐색은 원본 FPS 간격을 요청하지만 브라우저의 시간 정밀도 때문에 프레임 단위 오차가 가능하다.
  한 프레임 수준의 모호한 이벤트는 반복 확인한다. 원본/프리뷰 자체에 포함된 개인 영상은 로컬 검수자에게 보인다.
- 고정 카메라·연속 촬영·관절이 보이는 영상이 필요하다. 물보라·수중 가림·리플레이·장면 전환·선수 교차에서는
  완전한 카운트가 불가능할 수 있다. UI의 영법 선택은 자동 영법 분류가 아니다.
- 모델 처리 중 창을 닫아도 로컬 서버가 켜져 있으면 계속 처리된다. 서버 강제 종료 시 중단 상태로 표시한다.
  작업 오류는 해당 프로젝트의 `analysis.log`, 프리뷰 변환은 `preview.log`를 참고한다.

## QA 재현

핵심 자동 회귀는 `tests/test_video_workbench.py`에 있으며 GitHub Core job에서도 실행한다.
실제 영상의 UI·추론 검증은 로컬 서버가 켜진 상태에서 실행한다.

```powershell
python -m pip install playwright
python -m playwright install chromium
python scripts/qa_video_workbench.py --video "C:\path\swim.mp4" --start-sec 0 --end-sec 12
```

QA는 업로드한 프로젝트만 정리한다. 화면·보고서는 `tmp/analysis_v2/workbench-browser/`에 남는다.
버튼 테스트용 이벤트는 취소하고 최종 QA 기록은 판독 불가로 저장하므로 **독립 정답에 사용하면 안 된다**.

구현 참고: [imageio-ffmpeg](https://github.com/imageio/imageio-ffmpeg),
[FFmpeg 옵션 문서](https://ffmpeg.org/ffmpeg.html). 이 도구들은 로컬 호환 프리뷰 생성에만 사용한다.
