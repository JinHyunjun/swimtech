# v0.5.0 — 로컬 교차 검수실과 원본 좌표 단위 교정

상태: **오프라인 구현/실행 검증. 실영상 카운트 정확도는 미검증.**

## 사용자와 함께 확인할 수 있는 도구

`python -m analysis_v2.workbench`로 `http://127.0.0.1:8765`에서 별도 검수 사이트를 실행한다.
원본 업로드 → 구간/영법/선수 영역 선택 → 사람의 수기 기록 → 모델 결과 공개 → 후보 장면 비교 → 내보내기 순서다.
원본·결과·라벨은 로컬에 보관하며 운영 DB/클라우드 AI를 호출하지 않는다.
단일 ROI는 하나의 선수/레인을 대상으로 한다. 여러 선수는 프로젝트별로 분리해 검수하며,
같은 ROI에서 선수들이 교차할 때 신원 보존을 보장하지 않는다.

모델 결과를 열기 전 마지막으로 저장한 독립 라벨과 공개 후 보정용 라벨을 구분한다.
개별 라벨은 항상 `verified=false`. 두 검수자의 원본 해시·영법·시간 구간·ROI·시간축과
실제 독립 기록 여부를 확인해야 합의 비교에 사용할 수 있다. 테스트 버튼을 눌렀다는 사실은 정답이 아니다.

## 발견한 원인과 수정

### 1. 비정사각형 영상의 기하 왜곡

기존 좌표는 x/영상너비, y/영상높이로 각각 정규화했지만 몸통 축 계산에서는 두 축을
동일한 길이 단위로 취급했다. 9:16 영상에서 기울어진 몸통과 손목·발목의 투영이 왜곡될 수 있다.

신호 계산에 들어가기 전 x에 원본 `width / height`를 곱해 두 축을 높이 기준 단위로 맞춘다.
화면 표시/추적용 정규화 좌표는 유지하며 레인 크롭 회전 복원 후에는 원본 종횡비를 전달한다.
캐시에도 이 값을 저장한다. 크기 없는 기존 캐시는 비율을 추측하지 않고 명시적으로 레거시 상태로 남긴다.

3개 종횡비(9:16, 16:9, 1:1)와 기울어진 신체 합성 입력에서 신호 불변성을 확인했다.
실제 기존 포즈 캐시의 같은 관절·같은 구간에 비율만 적용한 결과는 다음과 같다.

| 동일 포즈 입력 | 팔 후보 | 킥 후보 | 전체 횟수 |
| --- | ---: | ---: | --- |
| 기존 단위 처리 | 13 | 12 | 팔/킥 신호 공백으로 보류 |
| 원본 종횡비 1080/1920 보정 | 14 | 12 | 팔/킥 신호 공백으로 보류 |

이는 기하 교정으로 예측이 달라졌다는 결과다. 14개가 실제 정답이라는 뜻도,
정확도가 13→14로 좋아졌다는 뜻도 아니다. 자동 출발/활주 인식이나 신경망 가중치 재학습은 하지 않았다.

### 2. HEVC 영상의 오디오만 재생되는 문제

실제 iPhone 영상은 HEVC였다. Chromium은 오류 이벤트 없이 오디오만 재생했고
`readyState=4`여도 `videoWidth=0`으로 빈 화면이 나왔다. 메타데이터 로드 검사만으로는 발견할 수 없었다.

원본은 보존하고 로컬 FFmpeg로 무음 H.264 프리뷰를 만든다. 540개 원본 프레임을 모두
유지한 720×1280 프리뷰와 약 29.984397fps 시간축을 확인했다. 분석은 계속 원본 1080×1920으로 수행한다.
프레임 수와 길이 불일치 시 업로드를 거절하고 부분 파일을 정리한다.
프리뷰는 원본 프레임 순서/FPS 기준이며 가변 프레임률 영상의 실제 촬영 시각을 정밀 복원한 결과는 아니다.

브라우저 QA도 실제 영상 너비/높이와 디코딩된 픽셀 변화량을 검사하도록 강화했다.
재생 버튼이 보인다는 이유만으로 성공 판정하지 않는다.

## 실영상 실행 및 QA 결과

로컬 자유형 영상의 5.7~17.7초, 사용자 제공 편도 25m, 전체 화면 ROI,
`lane-rtmpose` + `quality`(RTMPose-X/OpenVINO Intel GPU)로 실행했다.

- 원본 360프레임 분석, 포즈가 있는 프레임 337개, 트랙 1개.
- 측정 실행의 모델 구간 처리 116.509초, 약 3.09 처리 fps. 프리뷰/업로드 시간과는 별도다.
- 팔 후보 14개, 킥 후보 12개. 팔 0.800초·킥 0.634초의 최대 신호 공백으로 전체 집계 보류.
- 25m 입력은 반영됐지만 모델 DPS는 `null`로 유지. 후보 수로 강제 계산하지 않음.
- 핵심 회귀 241개(기존 204 + 로컬 검수/기하/라벨 37), Alembic 단일 head 통과.
- 실영상 브라우저 QA: 업로드·HEVC 프리뷰 표시·ROI 드래그·팔/킥 버튼/키보드·수기 저장·
  결과 공개·후보 시점 이동·JSON 다운로드·시험 업로드 삭제까지 통과.
- 1920/1440/1024/768/390/320px에서 문서 가로 넘침 없음. 결과 화면도 1440/768/390/320px 확인.

재현 스크립트: [`scripts/qa_video_workbench.py`](../../../scripts/qa_video_workbench.py).
QA 증적과 실영상 캡처는 무시된 `tmp/analysis_v2/workbench-browser/`에만 보관한다.
QA 수기란은 **팔/킥 모두 판독 불가·미검증**으로 저장했으며 실제 정답이나 정확도 표본이 아니다.

## 다음 정확도 개선을 위한 입력

이 도구에서 사람의 독립 이벤트 시점을 먼저 모아 가림, 좌우 팔 바뀜, 출발/활주 오검출,
피크 중복/누락을 구분해야 한다. 현재 검토 힌트는 관절 신뢰도 공백·위치 급변일 뿐
물리적 가림의 확정 라벨이 아니다. 실제 이벤트 정답이 확보되면 같은 포즈 캐시에 대해
횟수 오차·시점 precision/recall/F1을 비교하고, 그 뒤에 추적/시간 모델 변경이나 재학습을 진행한다.

이 단계는 공개 API/UI 활성화, 100% 카운트 달성, 정식 기능 릴리즈가 아니다.
따라서 공개 릴리즈 노트와 Notion 서비스 설명서의 정상 기능 목록에는 추가하지 않았다.
