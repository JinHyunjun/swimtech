# 다중 선수 카운터 v0.2 오프라인 검증 보고서

> 실행일: 2026-08-26
> 상태: 실험용 · 공개 API/UI 미연결 · 실제 횟수 정확도 미검증

## 결론

고정 레인 ROI와 레인별 90도 회전, RTMPose top-down 추론을 결합하자 한 프레임에서
놓치지 않고 찾은 레인은 평균 `1.868 → 4.897`로 증가했다. 이는 `+162.2%`의 검출
범위 개선이다. 60% 이상의 프레임에서 유지된 레인 트랙도 `7 → 93`개로 늘었다.

그러나 이 결과를 **스트로크·발차기 정확도 향상**이라고 부를 수는 없다. 무작위 시드로
고른 영법별 5개, 총 20개 방송 영상 구간에는 독립적으로 기록된 이벤트 정답이 없고,
특히 원거리·수면 위 영상에서는 발의 움직임을 사람이 프레임 단위로도 판독할 수 없는
경우가 많았다. 모델 예측을 다시 정답으로 사용하지 않았으므로 실제 횟수 정확도는
현재 `미검증`이다.

`산출된 트랙`은 결과가 존재한다는 뜻이며, 정답과 일치한다는 뜻이 아니다. 이번
실행에서 RTMPose 모델 파일은 매 표본마다 다시 초기화했으므로 처리 속도는 장기 실행
서비스의 상한·하한으로 해석하지 않는다.

top-down 방식이 빈 입력에도 포즈를 강제로 만드는지 검증하기 위해 검정·수영장색 단색·
무작위 노이즈 이미지도 별도로 입력했으며 세 입력 모두 0개 포즈로 보류됐다. 다만 실제
물보라·레인 로프를 선수로 오인하는 오탐률은 독립 프레임 라벨로 추가 측정해야 한다.

## 검증 절차와 발견 사항

1. 시드 `20260826`으로 영법별 5개 후보를 고르고, 단일 선수 분석 편집본 두 개는
   실제 다중 선수 경기 영상으로 교체했다.
2. 한 구간에서 레인 사각형이 유지되도록 HSV 히스토그램 기반 장면 전환 점수를
   확인했다. 처음 구간 중 9개에 화면 전환이 있어 동일 장면 범위로 다시 잘랐다.
3. 두 제공자 모두 6 FPS, 동일 구간, 동일 레인 다각형, 동일 카운터로 실행했다.
4. 개선 모델은 각 레인을 따로 잘라 수영 선수를 세로 방향으로 회전한 뒤 RTMPose를
   한 명 top-down 방식으로 실행하고, 좌표를 원본 화면과 실제 레인 번호로 복원했다.
5. 모델 예측을 숨긴 선수 중심 검수 시트를 만들었지만, 원본 방송 해상도에서 팔·발
   이벤트를 전 표본에 독립 라벨링할 수 없었다. 판독 불가 값을 추측하지 않았다.

## 다음 정확도 게이트

- 최소 200개 연속 레인 구간에 대해 팔 이벤트 타임스탬프를 사람 두 명이 독립 라벨링
- 발이 실제로 보이는 수중·측면 영상만 킥 정확도 평가에 포함
- 일치하지 않은 라벨은 제3 검수자가 확정하고 라벨러 간 일치도 기록
- 영상·선수·대회 단위 분리 후 ±1회 정확도, MAE, 미출력까지 포함한 종단 정확도 계산
- 장면 전환, 리플레이, 배속, 수중/수면 전환 감지 시 자동 분할 또는 결과 보류
- 팔 스트로크 MAE 1회 이하 및 평가 표본 90% 이상에서 ±1회를 달성하기 전 공개 기능 금지

스트로크·발차기 카운터는 정확도 게이트를 통과하지 못했다**는 것이다.
