# v0.4 카운트·DPS 검증 — 2026-09-08

상태: 오프라인 구현/회귀 검증 완료, 실영상 정확도 미검증.
비교 기준: `ff47b0e`의 v0.3 카운터. RTMPose 가중치는 동일하다.

## 원인과 변경

1. 팔과 발에 같은 0.3초 필터를 사용해 빠른 발차기의 진폭·위상이 손실됐다.
   킥은 0.09초 필터를 사용하고, 기본 CLI는 모든 원본 프레임을 처리한다.
2. 검출되지 않은 프레임은 배열에서 빠지므로 인덱스 기반 평활화는 긴 시간
   공백을 이어 붙였다. 실제 타임스탬프로 연속 구간을 나누고 짧은 공백만 보간한다.
3. 평활화 길이에 피크 비교 범위도 묶여 있어 느린 킥을 놓쳤다. 비교 범위를
   분리하고 더 높은 인접 피크에서 돌출도 탐색을 멈춰 잔떨림의 중복도 줄였다.
4. 빠른 킥 시점의 프레임 양자화로 독립 킥이 최소 간격 필터에서 합쳐졌다.
   피크 주변 세 점으로 프레임 사이 시점을 보정한다.
5. 양팔 평균 가시성만으로 한쪽 팔 미관측을 통과시켰다. 각 팔을 따로 검사한다.
   긴 팔/발 신호 공백이 있으면 진단 후보를 남기고 전체 횟수는 보류한다.

## 합성 신호 비교

`sin(2πft)`, 0~12초, 양·음 극값을 각각 한 비트로 정의했다. 정답은 식으로
계산했으며 사람이 매긴 실영상 정답이 아니다. 같은 신호를 v0.3과 v0.4에
입력하고 ±한 프레임으로 이벤트 일치를 비교했다.

남은 오차는 영상 끝에서 상승/하강을 충분히 보지 못한 마지막 이벤트다.
실제 물보라·가림·검출 오류를 포함하는 정확도로 해석하면 안 된다.

## 동일 실영상 포즈 비교

사용자가 자유형으로 확인한 로컬 영상의 기존 5.7~17.7초 구간을
RTMPose-X/OpenVINO/Arc GPU로 처리했다. 원본 29.984fps 중 360프레임을
처리하고, 동일한 337개 검출을 캐시에 저장해 v0.3과 v0.4에 각각 입력했다.

- v0.3: 팔 13회를 출력, 킥은 스트로크 비율 불일치로 보류.
- v0.4: 팔 13회·킥 12회의 **관측 후보**를 보존하되 전체 횟수는 보류.
- 이유: 팔 신호 최대 공백 0.800초, 킥 신호 최대 공백 0.634초.
  왼팔/오른팔 가시성은 59.9%/59.3%, 다리는 62.6%다.
- 원본 프레임/카메라 표본율은 29.984fps, 실제 포즈 관측률은 28.063fps다.
- GPU 추론 포함 118.848초, 저장된 포즈의 재분석 0.262초. 재분석 시간은
  신경망 추론을 생략한 값이므로 모델 FPS 향상으로 주장하지 않는다.
- 최초 실행에서는 이동 거리가 미상이어서 DPS를 계산하지 않았다. 이후 같은 날
  사용자가 **25m 풀에서 촬영한 수영**이라고 보충했다. 5.7초 프레임에서 출발 쪽
  다이빙, 17.7초 프레임에서 반대편 벽 도착을 확인해 해당 시도를 25m 편도 수영으로
  기록했다. 거리 출처는 사용자 제공 정보이며, 정확한 이륙/터치 시각을 독립 검증한
  것은 아니다.

### 25m 거리 입력 후 재검증

기존 포즈 캐시에 선수 `L01`, 5.7~17.7초, `distance_m=25`,
`distance_basis=interval_total`을 전달했다. 이 거리는 다이빙·잠영 이동을 포함한다.
수면 위에서 팔을 저은 구간만의 거리는 여전히 미상이다.

재실행 결과 거리 25m는 정상 반영됐지만,
`stroke_count_unavailable:arm_signal_gaps`로 DPS는 null을 유지했다.
이제 이 영상에서 DPS를 막는 주된 항목은 거리 미입력이 아니라 팔 횟수 미확정이다.
후보 13회에는 다이빙/입수로 발생한 움직임이 섞였는지도 검토해야 하므로,
25÷13을 확정 DPS로 기록하지 않았다.

재현 명령:

```powershell
python -m analysis_v2.cli .\video\이강해.mp4 --stroke freestyle `
  --pose-cache-in tmp/analysis_v2/runtime/local-freestyle-v04-poses.json.gz `
  --distance-segments tmp/analysis_v2/runtime/local-freestyle-distance-segments.json `
  --output tmp/analysis_v2/runtime/local-freestyle-v04-dps-25m.json
```

거리 입력과 화면 확인 근거는 로컬
`tmp/analysis_v2/runtime/local-freestyle-distance-context.json`에 보관했다.
거리 보충 직후의 v0.4 재실행에서는 카운터 코드·가중치를 변경하지 않았다.
그 뒤 진행한 v0.4.1의 출발·활주 분리와 거리 출처 `user_reported` 보존은
[별도 후속 보고서](2026-09-08-v0.4.1-phase-review.md)에 기록했다.

개인 영상·원본 포즈는 저장소에 포함하지 않았다. 로컬 결과는
`tmp/analysis_v2/runtime/local-freestyle-v04-replay.json`, 비교 자료는
`tmp/analysis_v2/runtime/v04-comparison.json`에 있다.

## DPS와 QA

`DistanceSegment`로 선수 ID, 시작/종료 시각, 실제 이동 거리, 거리 기준을
받는다. 해당 구간만 재집계하고 DPS와 사이클당 거리를 따로 반환한다.
자유형 13 m / 팔 13회는 1 m/스트로크, 6.5사이클 기준 2 m/사이클이다.
수영장 전체 길이를 부분 영상의 이동 거리로 가정하지 않는다.

회귀 검증에는 합성 9조건, 긴 누락 시간에서 가짜 피크 방지, 짧은 가림,
한쪽 팔 미관측, 실제 포즈 표본율, 네 영법 DPS, 반 사이클, 여러 선수·부분
구간, 팔 신호 공백, 잘못된 거리, 타 영상 캐시 거부, GPU 없는 CLI 재실행을
포함했다. 기존 파일의 33개에서 61개로 늘었다.

코드 검증은 실영상 정확도 검증을 대신하지 않는다. 현재는 전 영법·전 영상에
대한 완전한 카운트를 보장할 수 없으며, 독립 이벤트 정답과 실제 거리로
오차를 확인하기 전까지 공개 기능과 Notion 서비스 설명서는 갱신하지 않는다.
